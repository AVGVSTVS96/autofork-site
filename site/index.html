Fork anything. Keep your changes.

autopatch keeps your fork on top of upstream. When upstream breaks one of your changes, an agent rebuilds it.

$npx github:AVGVSTVS96/autopatch fork owner/repo
Get startedGitHub

One command.

It forks the repo, clones it and adds the workflow. Set CLAUDE_CODE_OAUTH_TOKEN first and it adds that secret too.

Already have a fork? Run init owner/repo inside it.

$ npx github:AVGVSTVS96/autopatch fork pingdotgg/t3code
autopatch follows pingdotgg/t3code (main).
AVGVSTVS96/t3code now keeps itself current with pingdotgg/t3code. It's cloned in ./t3code.

A patch is a folder.

A PATCH.md that says what the change does, and the diff beside it.

.autopatch/
  config.json
  window-title/
    PATCH.md
    window-title.patch

Changed the code?

Write the PATCH.md, then save the diff.

$ autopatch save window-title
saved 1 file to .autopatch/window-title. Commit and push.

Only an idea?

Push just the PATCH.md. The next heal has the agent build it.

$ autopatch status
  window-title  (not built yet)

On your schedule.

Updates are plain git. The agent only runs to heal. Both are cron lines you can change.

update
heal
00:0006:0012:0018:0024:00
Update
Every 6 hours. Git only. A patch that doesn't apply waits for the heal.
Heal
Daily. The agent rebuilds what no longer applies, and your verify command checks it.
Follow
A branch, or releases. Track upstream's main, or only its tagged releases.

Commands

fork owner/repo
Fork it, set it up and push.
init owner/repo
Set up a fork you already have.
save id
Save your changes as the patch in .autopatch/<id>.
status
Your patches, and changes no patch holds yet.
sync
What the workflow runs.
