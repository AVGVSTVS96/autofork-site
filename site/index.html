A patch is a note and a diff.

PATCH.md says what your change is for, in plain words. The .patch is how it was done last time. git uses the diff. The agent uses the note.

Intent

Show each split pane's full ID, like w1:p2, on the right side of its top border, behind a setting that defaults to off.

Invariants

  1. Use the ID herdr already produces. Never rebuild or shorten it.
  2. Never truncate an ID. Truncate the left title instead.

autopatch

The same loop as a CLI and a GitHub Action, for any fork.

Set it up in your fork.

init writes the config and a nightly workflow. add turns your uncommitted changes into a patch. sync runs the same loop on your machine.

on:
  schedule:
    - cron: "17 6 * * *"
  workflow_dispatch:

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with: { fetch-depth: 0 }
      - uses: AVGVSTVS96/autopatch@v1
        env:
          CLAUDE_CODE_OAUTH_TOKEN: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
