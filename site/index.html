A patch is a folder.

A PATCH.md in plain prose, and the diff beside it. It says what the change does, not which lines it touches, so an agent can rebuild it on whatever upstream looks like next.

Changed the code?

Write the PATCH.md, then save the diff.

$ autopatch save context-usage
saved 4 files to .autopatch/context-usage. Commit and push.

Only an idea?

Push just the PATCH.md. The workflow has an agent build it.

$ autopatch status
  context-usage  (not built yet)

Follows releases.

When upstream publishes a release, the workflow rebuilds your fork on it. Nightlies and other pre-releases are skipped. To follow a branch instead, set "follow": "main".

Release
Your fork is rebuilt on it. Patches that still apply go in with git, and the result is pushed as a signed commit.
Agent
Only when a release breaks a patch. It rebuilds the patch from its PATCH.md, and your verify command checks the build. If upstream already does what a patch asks, the patch is dropped.
Check
Hourly, git only. Between releases it ends in seconds. A failed rebuild isn't retried until upstream or your fork changes.

Yours to change.

fork and init write .autopatch/config.json. This is the one in my T3 Code fork.

.autopatch/config.jsonAVGVSTVS96/t3code
{
  "upstream": "pingdotgg/t3code",
  "follow": "releases",
  "verify": "pnpm install --frozen-lockfile --ignore-scripts && pnpm --filter @t3tools/web typecheck"
}
upstream
owner/repo, or any git URL.
follow
releases (upstream's newest release tag, skipping pre-releases) or a branch. Default: releases, or the default branch if upstream has no releases.
verify
The command that checks a build.
agent
The command that rebuilds a patch, prompt on stdin. Default: claude -p --dangerously-skip-permissions. For Codex: codex exec --dangerously-bypass-approvals-and-sandbox
green
When following a branch, false takes upstream's newest commit even when its checks failed.

.github/workflows/autopatch.yml is yours too: change how often it checks, and set up what verify needs (Node, Bun, Rust) before the autopatch step. The action takes heal: false to apply what still fits without calling the agent, if you want rebuilds on one schedule and heals on another.

Commands

autopatch --help prints this list.

fork owner/repo
Fork it on GitHub, set it up and push.
init owner/repo
Set up a fork you already have, from inside it.
save id
Save your changes as the patch in .autopatch/<id>.
status
Your patches, and changes no patch holds yet.
sync
Rebuild on upstream; an agent heals what no longer applies.

Options for fork and init

--follow releases | branch
What to keep up with. Default: releases, or the default branch if upstream has none.
--verify command
The command that checks a build.
